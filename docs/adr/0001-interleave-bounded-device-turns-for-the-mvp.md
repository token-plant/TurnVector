# Interleave Bounded Device Turns for the MVP

TurnVector accepts a bounded number of concurrent requests for multiple Models, but one serving process and one dedicated Device Executor OS thread execute at most one synchronized Backend Turn at a time. This is Cooperative Turn Interleaving: after each Turn Receipt is accepted by the Runtime Core, any remaining work competes from a fresh Scheduling Snapshot and Turn Plan before the same or another Model may run. The Runtime Event Loop, Runtime Core call sequence, and statically linked C++/MLX Adapter share the owner thread; no other thread accesses MLX state.

Owner affinity is a complete lifecycle rule, not only mutual exclusion. The same physical thread constructs, invokes, synchronizes, shuts down, and destroys every Adapter, MLX, stream, model, KV, cache, and related native state object. A mutex or serial queue that moves those operations among threads does not satisfy the rule because it can change thread-local execution context and breaks the single ownership chain used to validate partial outcomes and teardown. Logical per-Model Model Runtime capsules carry explicit owner-affinity tokens but all map to this one thread in the MVP; they are neither per-Model workers nor scheduling authorities. External threads may enqueue bounded coarse Runtime Events or set the certified Device Control Signal, but they cannot invoke the Backend Interface. Affinity determines who may execute a Plan; it neither selects that Plan nor permits its work to exceed the granted Turn bounds.

A logical Prefill is a sequence of Prefill Chunk Turns, never one full-prompt Turn. Each Plan supplies a target Engine Service, explicit work ceilings, and a certified hard execution bound; the Adapter converts that target into one safe token range, evaluates and synchronizes the required output and persistent KV/cursor state, and returns continuation in the Receipt. It cannot loop over later chunks before yielding. The Scheduler may grant a larger target when no sibling work is Runnable and a smaller target under contention, but both remain within the same certified bound and no fixed token or time constant is frozen by this ADR. Work that cannot expose such a resumable boundary is excluded from shared scheduling and is never routed automatically to Exclusive Mode.

This design postpones simultaneous cross-Model stream or thread execution rather than request concurrency. Multiple in-flight MLX Turns would change execution order, backend-state ownership, Engine Service attribution, peak memory, and latency interference; any future concurrent mode requires a separate architecture decision and correctness, attribution, latency, throughput, and memory certification for the exact co-running set.
