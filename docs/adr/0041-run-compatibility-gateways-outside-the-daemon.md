# Run Compatibility Gateways Outside the Daemon

TurnVector implements external protocol compatibility in a separate Compatibility Gateway process, not in the TurnVector Daemon and not in the private C-compatible C++/MLX shim. A gateway terminates one explicit external compatibility profile, translates it into one supported Data Plane major over the authenticated local Unix socket, and runs as a dedicated Data-only identity with no Control Plane access. Network TLS and authentication, rate limiting, exact external-model-to-immutable-Revision routing, tokenizer and chat-template execution, deterministic parameter defaults, bounded text streaming, and external error mapping belong to the gateway. Request Acceptance, Admission, scheduling, residency, resource policy, Backend execution, and all durable authority remain in the daemon.

The first profile is a deliberately narrow OpenAI Chat Completions-compatible text profile. It is a versioned TurnVector contract rather than a promise to mirror every field or future OpenAI change: unsupported and unknown fields are rejected, one external request owns one Data Plane connection for its lifetime, and neither process retries, replays, resumes, or transfers an accepted request after connection loss. Each gateway binary supports one external profile major and one Data Plane major; a different external protocol or incompatible profile is a separate process or coordinated replacement, not a generic in-daemon translation bridge.

This preserves the daemon's bounded local trust model and keeps Internet-facing policy out of the Device Executor and Runtime Core. It costs one additional process, a tokenization/text boundary, and a local protocol hop, but failures remain isolated: gateway loss cancels only its live Data Plane requests, daemon loss invalidates every gateway session, and gateway readiness never substitutes for daemon Service Readiness.

The detailed interface, lifecycle, bounds, error mapping, verification, and rollout gates are defined in `docs/plans/2026-08-19-compatibility-gateway-design.md`.
