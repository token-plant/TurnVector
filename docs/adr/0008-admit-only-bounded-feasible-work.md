# Admit Only Bounded, Feasible Work

Request Acceptance occurs after boundary validation, Ingress Budget reservation, and one-time Alias resolution, assigns a stable Request ID, and enters Preparing without claiming Admission. During Preparing the Execution Backend performs stateless validation and returns a Request Description containing an exact Capability Key, applicable Certification Record bounds, ordinary Cost Profile estimate, resource and output bounds, and residency requirements without allocating KV state or creating a request handle. Preparation has its own operational timeout. A non-resident Revision enters Warming and revalidates description and capability evidence after loading; a resident Revision proceeds directly. Only successful Admission atomically creates a capacity-ledger Resource Reservation and immutable Timing Commitment, after which Request Materialization creates private Backend state before Queued. Later Timing Profile changes apply only to new Admission. Actual allocation consumes reserved budget, unallocated remainder releases immediately at terminal state, and allocated memory enters Pending Reclaim until observed convergence. Activating a new Certification Record or changing a certified upper bound triggers Profile Revalidation; online estimate changes within fixed certified bounds do not alter the safety contract.
