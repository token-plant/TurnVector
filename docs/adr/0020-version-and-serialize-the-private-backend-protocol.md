# Version and Serialize the Private Backend Protocol

The daemon-created private IPC channel is an inherited socketpair and uses the Backend Protocol's length-framed Protobuf messages, independent major and minor versions, capability handshake, sequence numbers, and correlation IDs; native Rust or C++ structures never cross it. The Worker proves launch identity by echoing a one-time nonce and Daemon Instance ID on that channel before protocol negotiation; it never reconnects through a public socket. Every local protocol fixes a maximum frame size, rejects invalid declared lengths before allocating message storage, and feeds a bounded per-connection queue rather than relying only on Unix socket backpressure.

Startup requires equal Backend Protocol majors. That protocol family and major owns one canonical repository-tracked append-only `uint32` capability registry, the sole authority from which generated constants and manifest subsets derive: zero is invalid, a published ID is never reused, and removed meanings stay reserved while each minor selects subsets. CI rejects zero, duplication, reuse, unreserved removal, and registry-manifest disagreement. Each peer supplies bounded strictly increasing minor entries from its embedded Protocol Support Manifest, binding minor number to canonical descriptor SHA256 plus sorted unique `provided` and `required_peer` IDs. A duplicate, unsorted, or zero ID is a Protocol Violation. For an exact descriptor candidate, an unknown provided ID is ignored and omitted from the effective set, while an unknown required-peer ID rejects negotiation. Known requirements must be subsets of the peer's known provided set. Quantities use named typed fields whose schema declares `offered_max`, `required_min`, or `exact`: every required minimum must fit the peer's offered maximum, effective maxima are the minimum of peer offers, and exact values must equal. The handshake selects the highest common non-revoked candidate satisfying all these rules; no usable entry rejects Worker startup, while ordinary unknown optional Protobuf fields remain ignorable.

The build generates and embeds the manifest; startup fails if embedded content and generated descriptors disagree, and no mutable sidecar is loaded. Failures use a stable Structured Error containing error code, reason code, retryable flag, Request or operation correlation ID, an optional bounded typed-detail `oneof`, and optional human-readable text. Each detail variant owns one distinct versioned Protocol Capability ID rather than a generic detail umbrella and is authorized only when the selected minor defines it and the effective capability set contains that ID; unsolicited or unknown detail is a Protocol Violation and no client parses text for behavior. One Worker accepts at most one mutating command in flight. A separate bounded control channel carries only heartbeat, Resource Evidence, and idempotent cancellation by operation ID; Candidate Formation and state reads remain serialized. If IPC is lost before a mutation's outcome is unambiguous, the daemon never retransmits it: the Worker is terminated and every dependent operation fails. The Operation Watchdog escalates from cooperative cancellation through whole-process termination and bounded force termination. On daemon EOF, the Worker performs Orphan Shutdown at its nearest certified safe point rather than waiting to reconnect.
