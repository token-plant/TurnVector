# Stage Serving Readiness by Capability Profile

TurnVector ships the first serving-ready implementation as the P0 Serving Profile: one authoritative Control Store, one immutable Runtime Identity Record-bound Storage Qualification Record, serialized durable Control Mutation, bounded non-recovery Audit, fail-closed schema handling, exclusive installation-wide process ownership through the Daemon Instance Lock, and restart with empty inference state. Identity Anchor, Runtime Identity Lease, Runtime Metadata authority, Runtime Bundle, Restore, Clone, same-ID Storage Qualification Rebind, multi-authority repair, Compatibility Custody, and the complete Bounded Integrity Lifecycle are unavailable and cannot gate or be advertised by this profile. Corruption or storage-binding drift that P0 cannot reconcile fails closed and requires creation of a new runtime under the same installation lock rather than partial repair, inferred recovery, or a new lock path.

P0 Service Readiness requires the OS-lifetime installation-scoped Daemon Instance Lock, exact equality between the session-frozen Storage Qualification Record and immutable Runtime Identity Record binding, exact Control Initialization or later mutation classification, a valid sole current Control State Generation, matching P0 Audit Sequence State, no Pending Audit Envelope, an Audit chain under the epoch-fixed Audit Registry Identity, a healthy session write guard, fail-closed schemas, an initialized Device Executor and compatible C++/MLX Adapter, fresh Resource Evidence, and a serving operational state. Whenever any predecessor process initialized the Backend, including graceful same-ID restart, Daemon Failure, or P0 Runtime ID replacement, the Process Reclaim Barrier requires predecessor exit proved by acquisition of that unchanged installation lock before the fresh resource baseline; a Clean Shutdown Boundary, Shutdown Result, new Runtime ID, new payload path, pre-lock sample, or pre-exit sample is invalid. True first genesis with no predecessor Backend initialization is explicit. When an initialized prior session reserved a suffix, readiness additionally requires its verified Clean Shutdown Boundary or a synchronized Crash Tail Boundary; fresh genesis has no prior tail. Bootstrap completes exact pending envelopes before tail handling. It never consults or creates a Locator, Anchor, Runtime Metadata row, Audit continuation pointer, repair source, implicit latest qualification, or second Control selector.

P0 initialization, range reservation, Control Mutation, pending clear, retention, and shutdown all share the same pre-writer Storage Barrier Failure latch. An actually attempted required durability barrier failure keeps Readiness false, stops Device work and all later writes, retains the Daemon Instance Lock until OS termination, and exposes authenticated read-only status without durability retry, failure marker or failure Audit record, or clean-release claim. Initialization uses `initialization_outcome_indeterminate` without a Control Mutation Operation ID or Token; later mutation uses Control Outcome Indeterminate only after its Operation ID exists. Before allocating a Control Mutation Operation ID, P0 must durably provide the complete build-derived Control Mutation Sequence Headroom outside Terminal Sequence Reserve; every ordinary assignment charges it, bounded Fence interleaving cannot consume its protected Result slots, and Audit Degraded retains it. When an Operation ID exists, required Fence file/parent synchronization, Store commit/parent synchronization, post-append Audit file/parent synchronization or verification, and clear commit/parent synchronization failures return Control Outcome Indeterminate, make no unchanged-state claim, and fabricate no Result. Individual Fence stale attempts remain internal; bounded exhaustion closes the operation/headroom and reopens the Runtime Closure Gate through one ordinary sequenced nonpublication failure Result before typed busy. C19 Store success advances the owner and emits the dependent exact-envelope completion Effect; only that Effect's sequenced Result after pending clear releases the owner/headroom and acknowledges success. Ordinary Audit append failure before its required synchronization attempt remains Audit Degraded and retains the same exact stage. Sequence Exhausted, Storage Capability Missing, and unreconcilable Control or Audit evidence are likewise non-ready; because P0 has no Bundle, Restore, Clone, same-ID qualification rebind, or same-ID repair capability, continued service requires a new runtime rather than an implicit profile upgrade.

A trustworthy exact-absent Store outcome closes the mutation through its pre-sequenced nonpublication failure Result without activation, while an indeterminate outcome fabricates no Result. From mutation-owner creation through its terminal Result, P0 closes the Core-owned Runtime Closure Gate: every registered Core transition that would increase future sequence-and-Audit closure liability is rejected or deferred, while only nonincreasing progress over already charged obligations and read-only status that creates no Core object remain available. Audit Degraded and the post-C19 completion stage additionally reject discretionary Turn dispatch while preserving only bounded safety and closure work. Audit Safety Reserve prevents ordinary evidence from starving those records; when a mutation owner exists, their ordinary Event Sequences still debit its headroom and never borrow Terminal Sequence Reserve. Commit Barrier entry separately closes the exact Event Loop-owned Control Mutation Cancel Gate. Every authorized Control Mutation cancellation then completes before Core conversion without Event Sequence, Audit, or headroom use: an exact tuple receives `cancel_window_closed`, any other tuple receives opaque `commit_in_progress`, and response write or connection termination releases its ordinary reservation.

Pre-ID range reservation is unsequenced daemon infrastructure with no mutation Operation ID or Audit Record. Its required commit or parent-barrier failure still latches Storage Barrier Failure and keeps Readiness false, but cannot return Control Outcome Indeterminate or claim the predecessor high-water; a successor classifies the possibly published sequence state.

The later Integrity Serving Profile may add those capabilities only with their already defined durability, evidence, qualification, and recovery contracts intact. Service Readiness is evaluated against the build-declared profile and reports that profile externally, so staged delivery narrows capability scope without weakening a claimed capability.
