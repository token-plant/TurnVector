# Separate Scheduling, Execution, and Resource Authority

The Scheduler owns request lifecycle, Model fairness, timing obligations, and the pure Admission decision; the Execution Backend owns backend-specific inference state, exposes compatible Work Candidates, and performs directed Residency Transitions; the Resource Governor owns resource-safety classification and resource-driven residency policy. Scheduler and Governor state live together in one deterministic Runtime Core and change only through sequenced Core Events, preserving authority without turning them into independent asynchronous services or shared locked state. A trusted local caller selects Service Class. The Scheduler selects a Model and candidate under policy limits, while the Execution Backend chooses safe backend-specific Shape, Chunk, and Step details within those limits, keeping MLX mechanisms out of scheduling and resource policy.
