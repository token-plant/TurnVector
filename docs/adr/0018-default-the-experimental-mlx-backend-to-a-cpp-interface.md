# Default the Experimental MLX Backend to a C++ Worker

TurnVector first freezes and tests a language-independent Scheduler and Execution Backend contract with the Fake Execution Backend. The MVP's real MLX adapter runs as an experimental C++ Backend Worker behind a versioned local IPC Backend Protocol, so the Rust daemon does not depend on an unvalidated in-process FFI grain. The Rust workspace separates a serialization-independent Runtime Core from protocol DTOs and daemon I/O; the C++ Worker remains outside those crates. The MVP links the MLX implementation directly and has no plugin loader. Every shared-execution Backend Capability remains scoped by a Certification Record to the exact Model Revision, Worker and MLX builds, negotiated protocol capabilities, case coverage, and hardware/software Envelope; neither the C++ choice nor an observed run creates a universal Apple Silicon capability. If a binary Backend Plugin ABI is later required, it will use a versioned C function table and opaque handles with C++ source wrappers, not native C++ virtual interfaces or object layouts. Scheduler policy, domain types, protocol messages, and conformance tests must not claim that Rust per-op, mlx-c, a C ABI, or another FFI boundary has passed P-1C.
