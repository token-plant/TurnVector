# Serialize Bounded Residency Transitions

Every post-load Model Descriptor comparison in this decision, including abbreviated identity-and-hash wording below, runs the same private verifier over the complete raw frame and claims and requires exact equality with the registered sealed frame, Model Descriptor ID, typed Model Descriptor Hash, and nonzero vocabulary.

The Resource Governor may direct automatic model load, unload, and bounded allocator/cache reclaim, but the Execution Backend performs each variant through the same Residency Transition operation serialized on the single device loop at a synchronized safe boundary. It cannot overlap a Turn and receives an independent Residency Receipt. Its Residency Service is measured and limited separately from Engine Service. A transition declares Resource Impact, a conservative blocking bound, and safe cancellation behavior; shared execution requires that bound to fit all current timing budgets. Cache reclaim is Reclaiming, may leave Model Residency unchanged, cannot change request semantics, and neither changes ownership nor proves physical reclamation. Requests for the same non-resident Model Revision share one cancelable Residency Demand and a separate Residency Wait Timeout. After safety filtering, demands run FIFO by creation Event Sequence with stable Model Revision ID as the tie-breaker; Service Class cannot reorder Warming work because it has no inference timing commitment. Before loading starts, the Governor commits a separate Residency Reservation from the Model Descriptor for shared weights and runtime residency cost. Expired waiters fail and are removed without claiming an inference SLO or entering Exclusive Mode. Core acceptance of a successful load Result retains complete Backend residency ownership and the complete Reservation, advances Backend Generation, invalidates the Revision's pre-load Model Descriptor observation and all older not-yet-admitted Request Descriptions, and leaves it unavailable for Candidate Formation. The daemon then repeats `describe_model` over the exact registered Manifest and requires exact equality with the registered Model Descriptor identity and hash. Every bounded remaining waiter and unrelated resident Preparing request enters the same single bounded description-refresh path in stable Request ID order; unrelated Warming requests remain stale until their own successful-load gate. The loaded Revision's waiters use the fresh registered descriptor and current Generation before separate Admission. Any loaded-Revision descriptor drift fails its waiters and marks that Revision Unavailable without turning internal Generation change into an unrelated request rejection. A trusted terminal failed or cancelled load strongly rolls back to zero retained ownership before returning; its accepted Residency Result authorizes Core to apply the checked complete partition, releasing the proven never-allocated remainder and moving proven actual allocation into Pending Reclaim. An inconsistent or untrustworthy result invokes process-wide fail-stop. Load failure fails all waiters, marks the Revision Unavailable, and stops automatic retry until explicit Control Plane repair. Unload may start only after every request ownership has been consumed by accepted Request Release Results and no release is pending. Starting or logically completing unload releases no applicable charge; successful unload's accepted Residency Result authorizes Core to apply the same checked partition, while failed unload retains ownership and the complete Reservation.
