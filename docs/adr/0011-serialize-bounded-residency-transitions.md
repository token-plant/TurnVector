# Serialize Bounded Residency Transitions

The Resource Governor may direct automatic model load and unload, but the Execution Backend performs each Residency Transition as a serialized control operation on the single device loop at a synchronized safe boundary. It cannot overlap a Turn and receives an independent Residency Receipt. Its Residency Service is measured and limited separately from Engine Service. A transition declares Resource Impact, a conservative blocking bound, and safe cancellation behavior; shared execution requires that bound to fit all current timing budgets. Requests for the same non-resident Model Revision share one cancelable Residency Demand and a separate Residency Wait Timeout. After safety filtering, demands run FIFO by creation Event Sequence with stable Model Revision ID as the tie-breaker; Service Class cannot reorder Warming work because it has no inference timing commitment. Before loading starts, the Governor commits a separate Residency Reservation from the Model Descriptor for shared weights and runtime residency cost. Expired waiters fail and are removed without claiming an inference SLO or entering Exclusive Mode. Loading success revalidates Manifest and capability evidence before separate Admission for each remaining waiter. Loading failure fails all waiters, marks the Revision Unavailable, and stops automatic retry until explicit Control Plane repair. On unload, unallocated capacity releases immediately while allocated residency memory remains Pending Reclaim until observed convergence.
