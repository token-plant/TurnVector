# Use a Token-Native, Two-Phase Request Contract

The MVP Data Plane accepts input token IDs, one closed Generation Parameters value, required Service Class, a Model Alias or immutable Revision reference, required Max Output Tokens, an optional presence-tracked Sampling Seed, and bounded Stop Token Sequences; tokenization, chat templates, text decoding, and raw deadlines remain outside TurnVector. Every Generation Parameters field is explicitly present. Sampling Mode maps to `UNSPECIFIED=0` (invalid), `GREEDY=1`, and `CATEGORICAL=2`. Temperature and Top P preserve their accepted IEEE-754 binary32 bit patterns, while Top K is an unsigned 32-bit integer; omission, negative zero, NaN, or infinity is invalid. Greedy requires positive-zero Temperature, Top P exactly `1.0`, and Top K `0`. Categorical requires Temperature in `(0, 2]`, Top P in `(0, 1]`, and Top K either `0` for disabled or strictly below the registered Model Descriptor's nonzero vocabulary size. Service Class maps to `UNSPECIFIED=0` (invalid), `INTERACTIVE=1`, `STANDARD=2`, and `BACKGROUND=3`. The daemon supplies no default for an omitted or invalid field. P0 exposes no configurable logits bias, repetition, presence, or frequency penalty, Min P, XTC, or Backend-native opaque generation parameter.

Categorical token selection is exact. A non-finite model logit or non-finite binary32 cast fails the Turn before sampling. Over pinned-MLX binary32 tensors, the Adapter evaluates, in order, `centered = logits - max(logits)`, `weights = exp(centered)`, `normalizer = sum(weights)`, `log_probabilities = centered - log(normalizer)`, and `probabilities = exp(log_probabilities)`; it does not substitute `weights / normalizer` or a different softmax primitive. Top P `1.0` retains every token. Otherwise the Adapter stably orders tokens ascending by `(log_probability, token_id)`, gathers the separately computed probabilities, takes their inclusive binary32 cumulative sum, masks every entry whose cumulative value is less than or equal to binary32 `1 - Top P`, and retains the first entry that strictly crosses the threshold plus all later entries. If binary32 rounding yields no crossing, it retains only the greatest log probability, with lower token ID winning. Top K `0` performs no further filter; otherwise the Adapter retains the greatest `min(Top K, surviving_count)` entries, with lower token ID winning an equality. It then compacts only retained `(token_id, log_probability)` pairs in ascending token-ID order, subtracts the greatest compacted log probability so at least one finite zero remains, divides by Temperature, calls `random::categorical` only on that compact vector, and maps the resulting compact index back to its token ID. The support is never empty, and no masked vocabulary token can be selected even for the smallest positive binary32 Temperature or a zero-uniform/Gumbel-`-inf` draw. Greedy instead uses stable argmax with lower token ID winning and performs no categorical filter or draw.

The effective Sampling Seed is fixed before Request Acceptance. Every caller-supplied `u64`, including zero, is valid. When the field is absent, the daemon obtains exactly eight bytes from macOS `SecRandomCopyBytes`, interprets them as little-endian `u64`, supplies the value to Core before Acceptance, returns it with its daemon origin in the Acceptance response, and emits the origin and value in the ordered Audit Effect. CSPRNG failure rejects before Acceptance without a Request ID and never falls back to time, a process-global RNG, or a constant. The Adapter initializes the per-request Sampling State with `mlx::core::random::key(seed)`, whose pinned-build representation is `uint32[2] {high32, low32}`. For each Categorical token it calls `split(state)`, persists the first result as the next request state, and uses the second result as the sole categorical draw key. Greedy performs no split. Every sampled Categorical token advances exactly once even when stop-sequence handling hides it or retains it in an ambiguous suffix; batching and Turn order never substitute shared RNG state.

One Generation Semantics Identity is the Evidence Hash of a deterministically generated canonical descriptor that enumerates the Generation Parameters schema and complete allowed domain, exact token-selection algorithm, and Sampling RNG Schema transition. Double generation must reproduce its bytes and hash. The build embeds the same expected value in daemon Domain Types and the Backend Bootstrap Manifest-bound complete Backend Capability descriptor; Backend Initialization must return that descriptor exactly before Service Readiness. The verified identity enters the fresh Environment Fingerprint and Certification Envelope, and an applicable Certification Record must bind it and bound the worst case across its declared parameter domain; missing or changed identity invalidates cached applicability, while runtime observations cannot widen it. Native and qualification tests share exact vectors for enum and presence handling, cutoff equality, tied cutoffs, explicit zero, no-crossing/subnormal Top P, smallest positive Temperature, equal logits, survivor count below Top K, zero-uniform/Gumbel-`-inf`, compact-index mapping, omitted-seed replay, and multi-token state transitions. A qualification-only sampler tensor seam outside the production Backend Interface also injects NaN, positive and negative infinity, and finite wider values whose binary32 cast is non-finite; each must fail before RNG split, Sampling State advance, or output publication.

After revision-independent boundary validation and Ingress Budget reservation, the daemon resolves an Alias exactly once. If the resulting Revision is Unavailable, direct or Alias-based selection returns a Domain Rejection before Request Acceptance, assigns no Request ID, and never repoints the Alias automatically. Otherwise the daemon validates Top K against that Revision's registered Model Descriptor vocabulary size, checks input plus Max Output Tokens against its context limit, and fixes the effective Sampling Seed; any failure still occurs before Acceptance and truncation is forbidden. Request Acceptance then assigns a connection-owned Request ID and Request Status Version and returns the frozen Revision, effective Sampling Seed and origin, plus initial Preparing state without claiming Admission. Preparing obtains a stateless Request Description with the complete finite Capability Requirement Set; a non-resident Revision moves through Warming. Immediately before Admission, every request revalidates its frozen Revision, derives the complete exact-key closure under fresh environment evidence, verifies Certification Applicability for every Key, and checks Timing Profile, Resource Mode, the exact Runtime Overhead Bound Set's support and sequenced-event interference, fixed capacity for actual initial-Materialization, initial-Candidate-Formation and release Support Operation Obligations, one reusable Future Turn Support Entitlement with a complete Support Outstanding Credit Vector covering separate Receipt-observation and conditional-continuation-formation obligations versus rejection/local-stale formation plus terminal cancellation-membership-change formation, and all non-support resource components without re-resolving its Alias. Rejection at that point terminally fails the already-accepted request with a Structured Error and Terminal Tombstone, creates no Resource Reservation or Backend ownership, and makes no release call; the reason code and retryable flag tell the caller whether a new explicit request is meaningful. Every explicit retry receives a new Request ID and inherits no progress, output, ownership, Reservation, entitlement, or Authorized Capability Set, though the caller may preserve the Revision, input, Generation Parameters, and effective Sampling Seed for numerical reproducibility. Successful Admission atomically freezes the complete Authorized Capability Set, exact Runtime Overhead Bound Set, Timing Commitment, all three initial obligations, reusable Future Turn Support Entitlement/vector, finite per-Turn and terminal membership-change operation requirements, and composite Resource Reservation across the separate Core resource and support ledgers before Materialization allocates private KV and Adapter-owned Sampling State. One connection may own multiple bounded requests and may query or cancel only its own; disconnect cancels all of them according to whether Backend ownership exists, and a later connection cannot take ownership or query their Tombstones. Control Plane inspection and management cancellation remain separately authorized and audited. Sampling remains Batch-invariant. Output uses bounded live Output Frames and is never persisted or replayed. There is no cross-request Prefix Cache.
