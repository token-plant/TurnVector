# Use a Token-Native, Two-Phase Request Contract

The MVP Data Plane accepts input token IDs, generation parameters, Service Class, Model Alias or immutable Revision reference, required Max Output Tokens, immutable Sampling Seed, and bounded Stop Token Sequences; tokenization, chat templates, and text decoding remain outside TurnVector. After basic validation and Ingress Budget reservation, the daemon resolves an Alias exactly once. If the resulting Revision is Unavailable, direct or Alias-based selection returns a Domain Rejection before Request Acceptance, assigns no Request ID, and never repoints the Alias automatically. Otherwise Request Acceptance assigns a connection-owned Request ID and Request Status Version and returns the frozen Revision plus initial Preparing state without claiming Admission. Preparing obtains a stateless Request Description with the complete finite Capability Requirement Set; a non-resident Revision moves through Warming. Immediately before Admission, every request revalidates its frozen Revision, derives the complete exact-key closure under fresh environment evidence, verifies Certification Applicability for every Key, and checks Timing Profile, Resource Mode, Owner-Thread Support interference, and capacity without re-resolving its Alias. Rejection at that point terminally fails the already-accepted request with a Structured Error and Terminal Tombstone, creates no Resource Reservation or Backend ownership, and makes no release call; the reason code and retryable flag tell the caller whether a new explicit request is meaningful. Every explicit retry receives a new Request ID and inherits no progress, output, ownership, Reservation, or Authorized Capability Set, though the caller may preserve the Revision, input, parameters, and Sampling Seed for numerical reproducibility. Successful Admission atomically freezes the complete Authorized Capability Set, Timing Commitment, and Resource Reservation before Materialization allocates private KV and Adapter-owned Sampling State. One connection may own multiple bounded requests and may query or cancel only its own; disconnect cancels all of them according to whether Backend ownership exists, and a later connection cannot take ownership or query their Tombstones. Control Plane inspection and management cancellation remain separately authorized and audited. Input plus maximum output must fit the registered context limit, and overflow is rejected rather than truncated. Sampling remains Batch-invariant. Output uses bounded live Output Frames and is never persisted or replayed. There is no cross-request Prefix Cache.
