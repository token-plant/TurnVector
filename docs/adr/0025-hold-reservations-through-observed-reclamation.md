# Hold Reservations Through Observed Reclamation

Admission creates a conservative request Resource Reservation in a capacity ledger rather than physically allocating maximum KV or output buffers. Separately, every model load requires a Governor-owned Residency Reservation derived from its Model Descriptor for shared weights and runtime residency cost; this cost never belongs to the first Warming request. Actual allocations consume the applicable reserved budget, and unused committed capacity cannot be admitted elsewhere while active. Each output-producing Turn also reserves its maximum visible output slots. At request termination or model unload, reservation capacity never physically allocated releases immediately; allocated memory becomes Pending Reclaim and remains charged until Adapter allocator evidence plus daemon process-footprint convergence proves reclamation. After Daemon Failure, the next process inherits no live capacity ledger and remains behind a Process Reclaim Barrier until exclusive lifetime locks prove the old process is gone and fresh system Resource Evidence establishes a baseline after OS reclamation. A Reclaim Stall during a live daemon triggers bounded cache clear and idle-Model reclamation plus Guarded Mode, then follows normal Resource Mode escalation without ever fabricating free capacity.
