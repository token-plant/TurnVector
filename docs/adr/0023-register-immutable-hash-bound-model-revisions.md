# Register Immutable, Hash-Bound Model Revisions

The Control Plane registers each immutable Model Revision under a stable Model ID through a Model Manifest containing a canonical Artifact Root, typed artifact File Hashes, context limit, external tokenizer identity, expected Backend Capability version, expected typed Model Descriptor Hash, and provenance. Registration accepts only the private verifier's field-private Verified Model Descriptor, never independent caller or Backend bytes, identity, hash, or vocabulary fields. Before constructing a successor it rejects registration that would exceed the fixed binary Model Registry Limit of 256 or the independent 4,194,304-byte descriptor arena; every descriptor frame is at most 16,384 bytes, and neither capacity may borrow. The count includes every registered Revision, whether Available, Retiring, or Unavailable; Model Aliases do not count. The limit is no greater than the per-Revision outcome count fitting one complete bounded Clone or repair Receipt, so every valid registry remains portable without chunking. Each File Hash and Model Descriptor Hash carries its own schema version and digest. The C++/MLX Adapter accepts no ad hoc load path and validates registered artifacts before and after loading; the same private descriptor verifier runs at initial registration, Bootstrap, and after load, and exact sealed-value mismatch makes the Revision Unavailable. New content requires a new Revision. Revisions under one Model ID share one Model Weight and Model Ledger. Aliases resolve once before Warming and never automatically repoint around an Unavailable target. Unregistration marks a Revision Retiring, rejects new bindings, and removes it only after final request and Reservation release. These lifecycle and Alias states persist across restart; Residency does not.

Runtime Restore and Runtime Clone count every Bundle Revision regardless of lifecycle state and reject before `PREPARED` when that total exceeds the destination binary's Model Registry Limit; Aliases do not count, and neither operation prunes revisions or temporarily overrides the limit. Clone otherwise preserves manifests, aliases, and Certification Records unchanged without rewriting Artifact Roots. It derives Certification applicability separately, revalidates each artifact, descriptor, and Backend capability, and records complete per-Revision outcomes in the Maintenance Operation Receipt. Applicability mismatch leaves only the work uncertified, while artifact or Backend failure makes that Revision Unavailable and changes destination Semantic State meaning; neither blocks unrelated Revisions or global Readiness. Every later Adapter load repeats validation.
