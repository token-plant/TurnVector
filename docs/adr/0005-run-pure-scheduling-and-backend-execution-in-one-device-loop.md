# Serialize Runtime State and Device Execution Across IPC

The Rust TurnVector Daemon owns a Runtime Event Loop that exclusively owns one deterministic synchronous Runtime Core, while a separate C++ Backend Worker owns MLX state and one dedicated device-execution thread. Bootstrap initializes the Core's first expected Event Sequence after Audit Reconciliation has written any required Crash Tail Boundary; from there, boundary inputs are validated into Domain Types, assigned strictly contiguous Event Sequence and daemon Monotonic Time, and passed one at a time to `Core::handle(event)`. The Core stages the complete candidate state or controlled delta, ordered outcomes, and Effects, verifies every production Core Invariant, and atomically commits only on success; failure preserves the prior state and exposes no Effect. An unexplained in-run sequence violation or invariant failure enters global Core Fault, while an explicitly bounded unrecoverable reserved tail declared across a crash does not. Legal state conflicts return audited Domain Rejections. Effects carry Operation IDs, generations, stable order, and explicit dependencies; independent work may execute concurrently without deriving semantic order from completion timing. Every completion returns as an Effect Result Core Event, and duplicate, late, unknown, or generation-mismatched results never reapply state. The Core performs no I/O, async work, clock reads, serialization, callbacks, or MLX calls.
