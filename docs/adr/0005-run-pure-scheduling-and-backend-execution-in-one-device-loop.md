# Run Pure Scheduling and Backend Execution in One Device Loop

The Rust TurnVector Daemon owns one dedicated Device Executor OS thread. On that thread, the Runtime Event Loop exclusively owns one deterministic synchronous Runtime Core and the statically linked C++/MLX Adapter. Bootstrap initializes the Core's first expected Event Sequence after Audit Reconciliation has written any required Crash Tail Boundary; from there, boundary inputs are validated into Domain Types, assigned strictly contiguous Event Sequence and daemon Monotonic Time, and passed one at a time to `Core::handle(event)`. The Core stages the complete candidate state or controlled delta, ordered outcomes, and Effects, verifies every production Core Invariant, and atomically commits only on success; failure preserves the prior state and exposes no Effect. For a Backend Effect, the Event Loop calls the Adapter directly on the same thread, synchronizes the bounded operation, and feeds its in-memory Effect Result back before another Turn begins. Whenever any live Timing Commitment can next become Runnable, the Event Loop must pass one synchronized scheduling-trigger boundary before forming a fresh Scheduling Snapshot: it fixes a cut over the finite already admitted Core Event prefix, processes only that prefix plus the fixed nonborrowable mandatory-crossing allowance under the active Sequenced Event Interference Bound, and then forms the Snapshot and Turn Plan. This same path covers the first runnable plan, Receipt, Plan Rejection, local stale, a support Result, and idle re-entry; no result authorizes inline continuation or direct Snapshot formation, so a Prefill Chunk cannot conceal a full-prompt loop. Later ordinary events cannot overtake that scheduling point; later cancellation, disconnect, Critical, failure, or shutdown events consume the bounded crossing allowance, then coalesce or defer, or invalidate affected commitments and enter bounded fail-stop when deferral is illegal. There is no per-Turn channel, task wakeup, serialization, socket, or process boundary. External I/O threads may enqueue bounded coarse control events or set certified cancellation and safety signals, but they cannot mutate Core state or call MLX. An unexplained in-run sequence violation or invariant failure enters global Core Fault, while an explicitly bounded unrecoverable reserved tail declared across a crash does not. Legal state conflicts return audited Domain Rejections. Non-Backend I/O Effects carry Operation IDs, generations, stable order, and explicit dependencies; independent work may execute concurrently without deriving semantic order from completion timing. Every completion returns as an Effect Result Core Event, and duplicate, late, unknown, or generation-mismatched results never reapply state. The Core itself performs no I/O, async work, clock reads, serialization, callbacks, or MLX calls.

The single external Core Interface remains `Core::handle(CoreEvent) -> CoreTransition`. Its Implementation uses private pure Modules for Request Lifecycle, Scheduling and Arbitration, Resource Policy, Operation Ledger, and one atomic Transition Coordinator. Local invariants and incremental witnesses remain inside their owning Module; only bounded cross-Module conservation rules reach the coordinator. The serving path must satisfy the binary Hot-Path Work Budget, while full-state scans are limited to Bootstrap, replay, tests, and explicit diagnostics.
