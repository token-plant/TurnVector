# Use a Narrow In-Process Backend Interface

The daemon statically links one C++/MLX Adapter and invokes it only from the dedicated Device Executor thread. The Backend Interface is a narrow in-process seam, not a transport: no socketpair, Protobuf frame, capability handshake, message sequence, correlation ID, serialization, or per-Turn queue lies between Scheduler selection and MLX execution. The interface exposes only bounded Candidate Formation, Turn execution, Residency Transition, Resource Evidence, cancellation polling, and shutdown operations. Each mutating operation is invoked once, synchronizes before returning its typed result, and cannot overlap another Backend mutation.

The Adapter implementation and source-facing module interface are C++. Rust crosses the private integration seam through a minimal C-compatible shim with opaque owned handles and explicit create, execute, cancel-poll, resource-sample, and destroy operations. Inputs and results are bounded owned in-memory values; neither language retains references into the other's stack or object layout. C++ exceptions never cross the seam, and every native error becomes a typed result or process-wide fail-stop according to its certified safety contract. Adapter and MLX build identities plus one Backend Interface revision bind every Certification Record; compatibility is checked at build and Native Adapter Initialization rather than negotiated at runtime.

The Device Executor constructs and destroys all Adapter, MLX, stream, model, KV, and cache state on its owner thread. External threads can only enqueue coarse Runtime Events or set the bounded Device Control Signal; they cannot invoke the Backend Interface. The Operation Watchdog first sets cooperative cancellation and, if the certified next-safe-point bound is violated, terminates the whole daemon rather than detaching or restarting the owner thread. Restart performs ordinary Bootstrap with empty inference state. The MVP's coarse interface is the later architecture decision recorded by ADR 0018, which supersedes only the P-1C report's recommendation to defer every topology choice. P-1C itself remains RED: it supplies no relative-performance certification and establishes no permanent general FFI conclusion.
