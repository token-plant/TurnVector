# Use Cooperative Time Targets and Nonblocking Output

A Turn Plan supplies a target Engine Service, phase-specific work ceilings, and a certified hard execution bound rather than claiming hard preemption. A logical Prefill spans one or more Prefill Chunk Turns. For each Turn, the C++/MLX Adapter uses the immutable Cost Profile and current model, Batch, Shape, KV, and compile-cache state to translate the time target into one concrete token range within the work ceilings and hard bound; it evaluates and synchronizes the required output and persistent KV/cursor state before returning progress, continuation, and yield reason. It cannot execute the next chunk inline. With no sibling work Runnable, the Scheduler may choose a larger target to reduce graph, command, and synchronization overhead; under contention or shrinking slack it may choose a smaller target to protect latency. Neither path changes the certified hard bound, and this ADR freezes no numeric quantum. A miss of the ordinary target within that bound calibrates the Cost Profile, while exceeding the certified bound follows Bound Violation and capability quarantine.

Returning after one Prefill Chunk creates a fresh scheduling opportunity, not a mandatory Model switch. Once Core accepts the Receipt, the remaining Prefill work must compete through the ordinary scheduling-trigger path and receive a new Scheduling Snapshot and Turn Plan before it can start. The Turn Arbiter may immediately select the same request again when current safety, urgency, fairness, and optimization policy permits, but the Adapter cannot carry execution authority across the Receipt or consume a later chunk under the prior Plan. This rule bounds the current non-preemptible Prefill interval; an end-to-end next-token or fairness bound additionally depends on the scheduling-cut and intervening-Turn bounds, so one Prefill Chunk per Turn alone makes no TPOT or starvation guarantee.

Every Token Request declares Max Output Tokens. Admission budgets aggregate output capacity, but each output-producing Turn must acquire a concrete Turn Output Reservation for its maximum visible tokens before running; otherwise Output Backpressure makes it temporarily non-runnable, and the Device Executor never blocks on a client channel. Persistent backpressure through its configured timeout orders Cooperative Cancellation. Stop-token matching remains in the C++/MLX Adapter, which withholds the longest ambiguous suffix and does not publish matched stop tokens by default. Sampling State is independent per request and must be Batch-invariant. After Receipt acceptance and atomic state commit, each request may produce at most one bounded Output Frame for that Turn, containing contiguous token IDs, starting Output Sequence, resulting Request Status Version, and optional termination. Batch-member frames follow stable Turn Plan member order and publication follows explicit Effect order. Successful enqueue into the owning connection's reserved ordinary outbound capacity is Output Publication; a later socket-write failure becomes Client Disconnect and never retries or replays the frame. Every terminal transition also emits an independent terminal Status Update, so an optional terminal reason in the last Output Frame is only a convenience. When one transition produces both, its Output Frame is published before its terminal Status Update. Frames remain live, ordered, and at most once; the MVP has no acknowledgement, persistence, or retransmission.
