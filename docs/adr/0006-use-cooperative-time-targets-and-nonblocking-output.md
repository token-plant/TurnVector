# Use Cooperative Time Targets and Nonblocking Output

A Turn Plan supplies a target Engine Service time and explicit work limits rather than claiming hard preemption. Every Token Request declares Max Output Tokens. Admission budgets aggregate output capacity, but each output-producing Turn must acquire a concrete Turn Output Reservation for its maximum visible tokens before running; otherwise Output Backpressure makes it temporarily non-runnable, and the Device Executor never blocks on a client channel. Persistent backpressure through its configured timeout orders Cooperative Cancellation. Stop-token matching remains in the C++/MLX Adapter, which withholds the longest ambiguous suffix and does not publish matched stop tokens by default. Sampling State is independent per request and must be Batch-invariant. After Receipt acceptance and atomic state commit, each request may produce at most one bounded Output Frame for that Turn, containing contiguous token IDs, starting Output Sequence, resulting Request Status Version, and optional termination. Batch-member frames follow stable Turn Plan member order and publication follows explicit Effect order. Successful enqueue into the owning connection's reserved ordinary outbound capacity is Output Publication; a later socket-write failure becomes Client Disconnect and never retries or replays the frame. Every terminal transition also emits an independent terminal Status Update, so an optional terminal reason in the last Output Frame is only a convenience. When one transition produces both, its Output Frame is published before its terminal Status Update. Frames remain live, ordered, and at most once; the MVP has no acknowledgement, persistence, or retransmission.
