# Persist Versioned Control State, Not Runtime State

Before a P0 Control Mutation Operation ID exists, the synchronized owner-creation check jointly revalidates the complete mutation token, exact Prepared Carry Reservation, current Support Ledger Generation, current next assignable Event Sequence, and full build-derived headroom. Every nonfatal failure after carry creation closes that unowned carry and resumes ordinary support atomically with the no-ID result. Only a successful joint check may allocate the Operation ID and create the Core publication Effect/owner; abbreviated references below to complete token revalidation include this full set.

Within this decision, a stable zero-request-liability proof means a current witness from a pure Core validator held under the already closed Runtime Closure Gate. The validator is not a second gate; only the gate makes the witness stable because no permitted transition can recreate request liability before barrier entry.

Authoritative Control State, serialized durable Control Mutation, fail-closed schema handling, and restart with empty inference state apply to every Serving Profile. Identity Anchor, Runtime Metadata, Bundle, Restore, Clone, multi-authority repair, Compatibility Custody, and Bounded Integrity Lifecycle mechanisms in this decision apply only to the Integrity Serving Profile.

P0 Control Initialization is the only genesis authority. While already holding the Daemon Instance Lock, it acquires the installation qualification lock, accepts one complete proposed Configuration Snapshot, and requires the Installation Policy-selected exact Storage Qualification Record to be the Head-selected generation for the current Runtime Authority Volume, OS build, TurnVector build, and Storage Capability Profile. The offline qualifier never acquires a Runtime lock, so no reverse lock order exists. Initialization holds the qualification lock through the database-parent synchronization that publishes the immutable binding, then may release it. It generates the Runtime ID and History Epoch ID inside the daemon and requires empty initial Model, Alias, Certification, and model-scoped Configuration sets. One guarded `FULL` Control Store transaction publishes that immutable qualification binding in the Runtime Identity Record, Control State version one, its sole current pointer, the initial P0 Audit Sequence State, and the exact pending Event Sequence one Epoch Open; explicit database-parent synchronization completes publication. P0 accepts no caller-supplied identity, hidden daemon default, implicit latest qualification, Initialization Manifest, Runtime Locator, Identity Anchor, Runtime Metadata staging, or alternate current pointer. Initialization succeeds only after the exact Epoch Open is synchronized, verified, and cleared; an actually attempted required-barrier failure returns `initialization_outcome_indeterminate` without a Control Mutation Operation ID or Token.

After genesis, the unified durable Control Mutation publisher is the only authority that may advance P0 Control State, while only the separate guarded range-reservation primitive may advance P0 Audit Sequence State. Model registry, Configuration, and Certification modules validate and encode immutable rows only inside the mutation's caller-owned uncommitted transaction; they expose no commit, current-pointer, activation, or acknowledgement operation. Bounded candidate validation first proves the full build-derived Control Mutation Sequence Headroom remains inside already durable ordinary ranges, completing range reservation when necessary without borrowing Terminal Sequence Reserve; Sequence Exhausted or reservation failure occurs before a Control Mutation Operation ID, Effect, or owner exists. At a synchronized boundary the Runtime Event Loop revalidates the complete mutation token, current next value, and headroom; drift returns a no-ID state conflict. Only after that revalidation does the daemon allocate one Operation ID and Core atomically record the prepublication Effect, one-in-flight proposal owner, and headroom charge before requesting a Predecessor Fence. Every permitted ordinary assignment decrements it under the attempt/intervening-assignment limits. Individual Fence attempts return to daemon orchestration without a Core Event. The closed Runtime Closure Gate permits existing request work only through registered nonincreasing closure edges, and Commit Barrier entry requires a stable Core proof of zero accepted requests, Turn Plans, Timing Commitments, Future Turn Support Entitlements, request Backend ownership, pending releases, and output reservations. After that quiescence proof, a granted fence, and final token revalidation, entry assigns the protected Store-result slot to the pending Store publication Effect Result and submits the complete successor, pointer, and exact Pending Audit Envelope without changing sequence high-water. Disconnect of the originating Control Plane connection ends only mutation-result delivery; Data Plane Client Disconnect still cancels every owned request through its already budgeted transitions. Inequality is Storage Capability Missing and P0 has no same-ID rebind. An absent initialization or mutation transaction leaves the prior state; one exact committed candidate receives any missing parent barrier and exact pending-envelope completion; every third state enters non-ready custody. Bootstrap never rolls back to a retained generation, synthesizes a candidate from Audit or artifacts, or regenerates an envelope from a state diff. Missing, corrupt, or provenance-invalid P0 Control authority cannot be repaired under the same runtime and requires a new runtime. A restart rehydrates only the exact committed Control State, including complete registered Model Descriptor bytes, and begins with empty request, KV, Residency, Reservation, output, and connection state.
