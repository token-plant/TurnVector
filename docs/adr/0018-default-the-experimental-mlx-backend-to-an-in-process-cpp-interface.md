# Default the Experimental MLX Backend to an In-Process C++ Interface

TurnVector first freezes and tests a language-independent Scheduler and Execution Backend contract with the Fake Execution Backend. The MVP's real MLX implementation is an experimental C++/MLX Adapter statically linked into the Rust daemon and invoked directly on the Device Executor. Its C++ implementation is hidden behind a minimal private C-compatible shim with opaque handles and coarse Candidate Formation, Turn, Residency, evidence, cancellation, and shutdown operations; no C++ object layout, STL type, exception, serialized message, or per-op mlx-c call crosses into Rust. The Rust workspace separates a serialization-independent Runtime Core from public protocol DTOs and daemon I/O, while the Adapter remains an internal native module in the same process. The MVP has no plugin loader. Every shared-execution Backend Capability remains scoped by a Certification Record to the exact Model Revision, Adapter and MLX builds, Backend Interface revision, case coverage, and hardware/software Envelope; neither the C++ choice nor an observed run creates a universal Apple Silicon capability. If a binary Backend Plugin ABI is later required, it will use a versioned C function table and opaque handles with C++ source wrappers, not native C++ virtual interfaces or object layouts. This later architecture decision expressly supersedes the P-1C report's recommendation to defer every product topology choice: the MVP selects this coarse in-process seam. It does not alter the RED experiment result, certify relative performance, or establish a permanent general FFI conclusion.
