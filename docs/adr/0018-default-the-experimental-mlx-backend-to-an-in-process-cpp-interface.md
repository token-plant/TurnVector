# Default the Experimental MLX Backend to an In-Process C++ Interface

TurnVector first freezes and tests one language-independent Backend Interface with the Fake Execution Backend. The MVP's real MLX implementation is an experimental C++/MLX Adapter statically linked into the Rust daemon and invoked directly on the Device Executor owner thread. The coarse Interface covers owner-thread initialization returning exact implementation/capability identities plus versioned Backend Resource Signal and Backend Operation Bound Sets; stateless Model Descriptor and Request Description generation with a finite Capability Requirement Set; post-Admission Request Materialization and ownership-gated exactly-once Request State Release; Candidate Formation with exact authorized Keys; synchronized Turn execution; compare-and-set accepted-Receipt Cost Profile observation; explicit Exclusive operations; load, unload, and bounded allocator/cache-reclaim Residency Transition; contract-bound Backend-only resource sampling; and shutdown. Before initialization, the daemon verifies a build-generated embedded Backend Bootstrap Manifest that binds the expected complete Backend Capability descriptor and other descriptor identities plus the externally certified initialization blocking/safe-point entry, then starts the watchdog from that entry; the returned complete descriptors must match before any later call. The Backend claim never certifies itself. A Receipt-producing `execute_turn` direct-call interval is Engine Service, while a pre-execution Plan Rejection interval is Runtime Overhead. Every other readiness-time call has a finite blocking and next-safe-point bound under the daemon-owned Owner-Thread Support Budget, Residency Service gate, or shared-paused Exclusive contract. Cancellable operations receive a read-only Device Control Signal view rather than a second command call. The Backend neither assembles complete Resource Evidence nor decides Certification Applicability, Admission, Resource Mode, or cross-Model policy.

The C++ implementation is hidden behind a minimal private C-compatible shim with opaque owned handles and one coarse entry point per Interface operation; no C++ object layout, STL type, exception, serialized message, or per-op mlx-c call crosses into Rust. A trustworthy synchronized result may report typed partial progress, allocation, or cleanup, but an operation that cannot return such a result triggers process-wide fail-stop and never fabricates an indeterminate Turn Receipt. Backend Shutdown is the final exactly-once owner-thread operation after readiness is false, no operation is in flight, and request ownership and pending releases are zero. Only a successful Shutdown Result proving zero logical Backend ownership permits a Clean Shutdown Boundary; it never proves physical reclaim, and failure is fail-stop with no retry or fabricated Result. The shim's raw deallocator is typestate-restricted to an empty handle after trustworthy initialization rollback or successful Shutdown Result; a live initialized handle is rejected, so raw destruction cannot bypass the typed operation or Clean Shutdown Boundary gate. The Rust workspace separates a serialization-independent Runtime Core from public protocol DTOs and daemon I/O, while the Adapter remains an internal native module in the same process. The MVP has no plugin loader.

Every shared-execution Backend Capability remains scoped by a Certification Record to the exact Model Revision, Adapter and MLX builds, Backend Interface revision, complete Backend Capability descriptor identity, case coverage, and hardware/software Envelope; neither the C++ choice nor an observed run creates a universal Apple Silicon capability. If a binary Backend Plugin ABI is later required, it will use a versioned C function table and opaque handles with C++ source wrappers, not native C++ virtual interfaces or object layouts. This later architecture decision expressly supersedes the P-1C report's recommendation to defer every product topology choice: the MVP selects this coarse in-process seam. It does not alter the RED experiment result, certify relative performance, or establish a permanent general FFI conclusion.
