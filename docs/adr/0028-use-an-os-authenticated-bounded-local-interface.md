# Use an OS-Authenticated, Bounded Local Interface

Authenticated Bootstrap status returns Daemon Instance ID, one nonzero checked `u64` Bootstrap Evaluation Generation, exact Condition Model and Action Decision Table identities, and four separately bounded typed fields from that immutable evaluation: confirmed conditions, blocked checks, one Primary Required Action, and at most eight Alternative Recovery Actions from the same row. A Daemon Instance starts at one and repeats it only while canonical bytes for both artifact identities, sorted typed inputs, check outcomes, selected actions, and prerequisite states remain equal; observation time and diagnostic text are excluded. Any included change checked-increments generation, while before overflow the process publishes no new status and exits and the next Instance starts at one. A prerequisite is `met` only when that evaluation verified it true, `unmet` when safely false but externally satisfiable, or `blocked` when exactly one named Blocked Check prevented verification. Every structurally possible route is emitted even with unmet or blocked atoms; a proved-impossible route is omitted, and command execution revalidates rather than accepting generation as authority. Each action ID appears once with a sorted unique conjunctive list; OR, NOT, nesting, free text, duplicates, and Primary repetition are Protocol Violations.

Control Hello and authenticated status return `initialization_manifest_binary_max_bytes` and process-fixed `initialization_manifest_repair_effective_max_bytes` as unsigned 64-bit values. The latter constrains only incoming repair bytes and never invalidates intact provenance or Readiness. An oversized request returns non-retryable stable `manifest_repair_limit_exceeded` before Hashing. Only when the selected Control minor defines the variant and the effective capability set contains its distinct registered `manifest_repair_limit_detail_v1` ID may `ManifestRepairLimitDetail` contain exactly unsigned `request_bytes`, `effective_max_bytes`, and `binary_max_bytes`; it carries no content, Hash, path, or source. An older negotiated minor or peer without that capability receives the same reason without detail. The reason means Policy replacement plus daemon restart and changes no durable condition or action-table input.

The Initialization Manifest binds every prune target's filesystem UUID, 64-bit `ATTR_CMN_FILEID`, and no-follow object type, plus File Hash for regular content and creation-time `st_nlink == 1` for each regular target. The volume must be qualified for persistent and 64-bit object IDs; link count, path, `st_dev`, `st_gen`, timestamps, and equal bytes are not identity. Fixed-owner staging permissions exclude untrusted concurrent writers. Full-target preflight retains parent descriptors, and immediately before `unlinkat` each removal revalidates parent, no-follow identity, type, File Hash, and regular-file link count. This does not claim atomic compare-and-unlink against authorized same-UID or root mutation inside the Local Trust Boundary. A multiply linked regular target is never unlinked and returns ID 7 `multiple_links`; there is no force or skip, so after restoring `st_nlink == 1` the operator reruns that complete preflight from the beginning. IDs 1-6 remain `identity_changed`, `type_changed`, `parent_unavailable`, `directory_not_empty`, `permission_denied`, and `io_failure`; optional syscall, `errno`, and text are non-authoritative.

Initialization Manifest Repair compares the framed raw-byte length with the process-fixed Effective Maximum before allocation, Hashing, or candidate copy. Oversize receives `manifest_repair_limit_exceeded` even when bytes would match the Locator, with Policy replacement and daemon restart as the only remedy; the response creates no persistent Bootstrap fact. Only an in-limit request is Hashed, strictly decoded, and checked against identity and ordinary prerequisites before evidence copy or `PREPARED`. An already present valid Manifest is verified under its Binary Maximum regardless of the lower repair Policy limit.

Authenticated status for a pending Rebind with absent or invalid exact custody names Rebind Tool Custody Restoration as Primary Required Action and exposes qualifying new-ID Clone as an Alternative Recovery Action with exact prerequisites. The offline restoration command accepts exact custody bytes, revalidates the unchanged token digest, synchronizes the candidate-qualified destination, and returns a bounded non-authoritative result; it never creates or resumes a Runtime operation and writes no Runtime Receipt or Audit evidence.

A pre-Locator prune response reports an unexpected child only as its Manifest-listed parent outcome `failed` with stable reason `directory_not_empty`. The interface returns no unknown child names or contents, accepts no recursive-enumeration option, and continues returning one bounded outcome for every later Manifest entry.

The Maintenance protocol defines one bounded Initialization Manifest Repair request carrying only raw Manifest bytes. It has no claimed hash, Runtime Bundle path, source-kind selector, or server-side Bundle reader; the daemon computes the File Hash and requires equality with its unique Locator selection. A CLI convenience command may fully verify an operator-supplied Bundle and extract its exact Manifest bytes before invoking this request, but that preprocessing adds no authority or durable provenance field.

When Manifest repair is blocked by exactly one repairable Metadata or Audit prerequisite, the daemon exposes only that exact prerequisite command if all of its independent prerequisites pass. Success closes the maintenance connection and requires process restart plus fresh Bootstrap before any next repair. Metadata and Audit damage together expose no repair command. When Manifest absence and Locator Degraded coexist, Locator Repair remains unavailable until Manifest repair completes and a fresh Bootstrap verifies it. No interface accepts a compound repair intent.

A Rebind resumer whose token-bound custody bundle is absent or invalid performs no Runtime write. With fresh offline authorization it may install only independently supplied bytes whose fully verified digest equals the unchanged token, synchronize them on the candidate-qualified custody volume, and then execute the exact candidate tool. If those exact bytes cannot be obtained, the interface reports same-ID Rebind pending and offers no token mutation, abandonment, or rebuild path; a separate new-ID Clone may consume only an already existing valid Runtime Bundle.

Pre-Locator prune receives the exhaustive canonical Manifest entry list, including every file and directory in children-before-parent order. It never requests recursive removal or discovers targets from directory contents. An unexpected child makes only the parent entry `failed`, and the bounded response continues with every remaining listed target.

The MVP exposes no network listener. Before binding any socket, acquiring a daemon or Runtime lock, or trusting Runtime bytes, the daemon reads exactly one bounded Installation Policy image from one installation-fixed absolute path. The opened object must be a non-symlink regular file owned by UID 0 and not writable by group or other. Its encoding is strict bounded UTF-8 JSON with one root object: duplicate keys, unknown fields, invalid Unicode, floats, exponent notation, negative or out-of-range integers, non-integer numeric values, and trailing non-whitespace bytes are rejected; every list count, string length, integer, and total byte size has an immutable binary maximum. The administrator CLI writes one deterministic human-readable representation for review, but acceptance does not require that representation because Installation Policy Identity is exactly `{format_version, SHA256("turnvector.installation-policy" || exact_file_bytes)}` without semantic re-encoding. Invalid location, type, ownership, mode, size, format, or identity computation terminates startup with a stable exit status before Service Liveness; no root-only socket, cached policy, or last-known-good fallback exists. The validated snapshot remains fixed for the process lifetime, so administrator replacement requires restart to affect connections. The administrator may intentionally restore any valid prior image because the local trust model adds no policy anti-rollback counter; operations and evidence bind the exact identity that governed them.

The Policy contains four distinct UID/GID allowlists: Data, Control, live maintenance, and offline maintenance, plus deployment Repair Evidence limits and filesystem safety margin. On macOS, each accepted Unix `SOCK_STREAM` connection obtains the connect-time effective UID and kernel group list through `LOCAL_PEERCRED`; a match against either the relevant UID or GID entries is required in addition to restrictive socket permissions. Offline tools snapshot and validate the same Policy once before lock acquisition and compare their effective UID and kernel process groups against the offline-maintenance list. Root has no implicit authorization bypass, and no username, directory-service lookup, executable identity, path access, bearer credential, or runtime command grants authority. Maintenance remains on the Control socket and additionally requires the live-maintenance list. Socket paths include the protocol-family major version, and each connection uses one bidirectional length-framed Protobuf stream whose first frame is the plane-specific Hello; each binary implements one major per family.

Hello reports family, major, bounded strictly increasing minor entries binding each number to canonical descriptor SHA256 plus sorted unique numeric `provided` and `required_peer` capability IDs, directional typed limits, build identity, and embedded Protocol Support Manifest hash. Each protocol family-major owns one append-only capability registry; zero is invalid, IDs are never reused, and removed meanings remain reserved. Duplicate, unsorted, or zero wire IDs are Protocol Violations. Unknown provided IDs are ignored, unknown required-peer IDs reject negotiation, and each known required set must fit the peer. Named negotiated quantities retain offered-max, required-min, or exact semantics. The highest common non-revoked entry returns effective capabilities, limits, Daemon Instance ID, and the fixed Installation Policy Identity. Control Hello and authenticated status also return immutable `model_registry_limit`; registration, Restore, and Clone independently enforce it. Maintenance Capability exists only for that authenticated Control connection when its effective capability set contains the registered ID and its peer credentials also match the snapshot's live-maintenance allowlist. It expires on disconnect and cannot cross a Daemon Instance ID change; a reconnect must authenticate and negotiate again before creating, inspecting, or resuming live maintenance work. Expiry does not cancel or roll back an already durably accepted operation. Only that live command scope may introduce a new trusted-tool Operation ID, which must not collide with visible staging or tombstones; all other caller-supplied IDs may only resume an existing exact intent. Initialization Manifest Repair is one such live non-ready command: its request carries externally supplied bounded bytes whose exact File Hash must equal the Locator selection, and no interface permits a replacement hash or content choice. The command is offered for two agreeing valid Locator slots or one uniquely identifying degraded slot only after Anchor, current qualification, Metadata publication, and Audit checks pass; a separately reported Control failure does not hide it. Write durations remain frozen per connection. Build and whole-manifest hashes are diagnostic; selected descriptor equality remains mandatory. Offline Bundle capture or registration, Migration, Storage Qualification Rebind, Restore, Clone, and either prune command never synthesize Maintenance Capability. The pre-Locator prune command completes authorization, exact-Manifest, absence, object-type, and full-target preflight before removal, retains opened parent descriptors, then uses no-follow descriptor-relative revalidation and removal for every canonical target despite individual failures. Missing is `already_absent`, a matching target may become `removed`, and any changed identity, symlink, or special object is `failed`; no result rolls back. Its bounded non-authoritative report carries the selected Manifest Hash and exactly one outcome per target; success requires every target absent, a crash returns no report, and rerun recomputes all outcomes. It persists no Runtime Receipt or Audit evidence.

Every maintenance Intent and any Receipt bind the governing Installation Policy Identity and effective policy-derived values. Immediately before the first `PREPARED` transition, the daemon or offline tool reopens and validates the fixed path and requires its identity still equal the operation snapshot; mismatch before publication changes no Runtime authority and requires restart or a new operation. Once `PREPARED` is durable, its bound historical Policy Identity and effective values remain the immutable operation semantics, but they grant no future operator authority. Every explicit creation or resume authenticates the requesting peer or process against the current valid Policy: a removed credential cannot explicitly resume, while a newly authorized credential may finish the exact old intent only under its bound limits. Bootstrap is different: after validating that a current Policy exists and acquiring the identity locks, it may automatically perform only deterministic predecessor/candidate reconciliation already authorized by an eligible durable `PREPARED` token, using exact staged bytes and bound semantics. A Storage Qualification Rebind token is not eligible: before that token is written, the candidate build must place its self-contained exact tool bundle and every non-system dependency as strict fixed-owner regular files on a candidate-qualified Identity-root custody volume and bind the canonical whole-bundle digest rather than a path. Every explicit first execution or resume reopens without following links and verifies modes, manifest, all File Hashes, and the bound digest; a mismatch refuses execution. Custody deletion is forbidden through `COMPLETED`, later cleanup is explicit, Bootstrap reports the pending Rebind without `CLAIMED`, and only an explicitly reauthorized invocation of that exact candidate-build tool may resume. Bootstrap otherwise requests no credential, makes no new choice, creates no new intent, and never continues pre-`PREPARED` staging. This makes revocation immediate for discretionary action without allowing a published authority transition to remain permanently split.

A Data Plane connection then multiplexes typed request, cancellation, status, and output frames. It may pipeline only a negotiated bound on outstanding command count and bytes. Each command carries a nonzero, strictly increasing unsigned 64-bit connection-local Command ID; repeats or regressions are Protocol Violations. Every structurally valid command consumes its ID, including one rejected as Overloaded or by the domain, so retry uses the next ID. After structural validation and before Event Loop admission, the daemon reserves one slot and maximum encoded bytes for that command's Direct Response and holds it until the complete frame is written or the connection terminates; enqueue converts reserved bytes to actual frame occupancy. If ordinary response capacity is unavailable, one separate fixed rejection reservation can return the bounded rejection; if neither can be secured, the connection closes. Output cannot consume either response reserve.

Exactly one Direct Response echoes the ID for each legal command while the connection remains live; request state, output, and terminal status are separate events, and nothing is replayed after disconnect. Receive order determines Event Loop order, but Direct Responses may complete out of Command ID order. The complete Direct Response is written before causally produced Status or Output; socket failure leaves delivery unknown without replay, and frozen write deadlines close a stalled connection. A published Control Mutation whose Audit barrier fails returns stable `outcome_indeterminate`, including daemon Operation ID and current Control Mutation Token, rather than a generic I/O error or unchanged-state claim. While that failed session remains live, authenticated status also returns its structured in-memory Barrier Failure Observation: session, optional Operation ID, authority kind, phase, registered object role, syscall, errno, elapsed time, deadline, and `outcome_indeterminate`; no durable status contract exists after process exit. Cancellation Accepted follows the Core cancellation event but not terminal state. Command ID `u64::MAX` closes ingress while preserving existing events and disconnect detection. Bounded reservations, queues, ingress budgets, and terminal capacity prevent hidden growth; protocol violations close after at most one safe error, while Domain Rejections preserve the connection. Metrics remain bounded and content-free. The C++/MLX Adapter loads only registered hash-bound artifacts. This boundary protects against unauthorized peers, malformed clients, accidental artifact changes, and native Adapter failure; host, root, and authorized same-UID processes remain trusted.
