# Bound Waits, Leases, and Shutdown

Preparing, Warming, and Output Backpressure have separate configured timeouts: Preparation Timeout fails a request that cannot obtain a Request Description, Residency Wait Timeout explicitly fails a Warming waiter, and persistent backpressure orders Cooperative Cancellation. None creates an inference SLO or automatic Exclusive entry. An Exclusive operation may have no total-duration limit only while a Control Plane Exclusive Lease remains renewed; disconnect or expiry cancels at the next certified Exclusive Safety Point. Terminal request status is retained only in count- and time-bounded Terminal Tombstones containing no output content. After eviction, an authorized owning connection can return stable Gone only for a current-instance Request ID at or below its connection-local Request High-Water Mark; this avoids an unbounded completed-request table without misclassifying foreign or unissued IDs.

A build-time checked formula sums the worst-case required terminal Audit Records for every simultaneously live request, connection, control, and operation plus Critical, Device Executor Failure, repair, and shutdown, with one record per transition and no aggregation assumption; immutable binary maxima and state-machine tests prove the resulting Terminal Sequence Reserve. Ordinary work and P0 Control Mutation Sequence Headroom cannot consume or borrow it. Sequence Exhausted performs no further Audit write, retains every lock required by the active Serving Profile, exposes authenticated read-only status, and exits only by OS signal. P0 cannot rotate the epoch and requires a new runtime; the Integrity Serving Profile may carry the exact terminal unclosed interval only through its Bundle workflow.

Audit Safety Reserve independently provides nonborrowable Audit queue count-and-byte capacity from the same terminal-transition maxima and maximum encoded record sizes. Ordinary evidence cannot consume it, so ordinary queue saturation and Audit Degraded cannot starve already admitted cancellation, disconnect, Critical, Device Executor Failure, shutdown, or bounded already-admitted closure records, including P0 Runtime Closure Registry-approved nonincreasing transitions before the corresponding sequence reserve is used.

Graceful Shutdown uses the reserve to reject new work, cancel and release all live work at certified safe points, invoke exactly one owner-thread Backend Shutdown, validate its zero-ownership Shutdown Result, and confirm raw deallocation of only the resulting empty shell before strongly synchronizing a Clean Shutdown Boundary. The Daemon Instance Lock remains held through that Boundary and the last daemon instruction and is released only by OS process termination. Neither Shutdown Result nor Clean Shutdown Boundary proves physical reclaim: every successor after Backend initialization must acquire that unchanged lock and then establish a fresh Process Reclaim Barrier baseline, including a graceful same-ID restart. P0 has no Anchor or `CLEAN_RELEASED`: its exact Boundary alone closes the unused suffix. The Integrity Serving Profile additionally writes a matching Anchor `CLEAN_RELEASED`; if only that final Anchor write fails, the next Bootstrap still recognizes the exact prior-session Boundary as a clean tail. A missed safe point, missing or untrustworthy Result, failed deallocation, Storage Barrier Failure, or Boundary failure permits no retry, fabricated result, explicit unlock, or clean claim and leaves crash-tail recovery to a successor process.
