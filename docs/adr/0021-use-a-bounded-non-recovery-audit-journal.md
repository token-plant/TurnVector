The daemon writes no Runtime Audit record, failure marker, or clean release; the next process performs ordinary startup and derives Audit state anew.

Every Audit Record is exactly `u32_be length | u64_be Event Sequence | u32_be record kind | payload | u32_be CRC32C`. The bounded length covers every following byte in that record, and CRC32C covers the encoded length, sequence, kind, and payload while excluding only the CRC field itself. The declared length is validated against a binary hard maximum before allocation. Payload is a record-kind-specific bounded Protobuf message under an independent Audit Schema Major. Each major owns one canonical repository-tracked append-only `u32` kind registry: zero is invalid, published kinds are never reused, removed meanings remain reserved, and generated decoders plus fixtures derive from the registry. Canonical registry bytes and the deterministic Protobuf descriptor set have separate hashes, so Audit Registry Identity is exactly `{major, registry_hash, descriptor_hash}`. Each History Epoch fixes that identity and one Audit Head Hash Schema Version in Epoch Open, every Segment header, the Anchor, and every Bundle. Its domain-separated Epoch Genesis Hash binds Runtime ID, History Epoch ID, registry identity, and head schema; it is the predecessor of the Event Sequence one Epoch Open rather than a zero or absent value. Each framed record then advances Audit Head Hash over the domain tag, full registry identity, predecessor Audit Head Hash, and exact framed bytes; its Audit Record Identity is `{event_sequence, audit_head_hash}`. Neither Audit Registry Identity nor Audit Head Hash Schema Version changes inside an epoch. A binary writes only its current identities and embeds a bounded set of historical identities solely for verified inspection and Bundle capture; an older active epoch enters Migration Required and cannot receive new records. Either identity's evolution requires Bundle plus Restore or Clone into a new epoch. Unknown or mismatched identities and record kinds are never guessed. Only a final incomplete or CRC-invalid record may be discarded automatically; earlier corruption enters Audit Repair Required.

Explicit Audit repair runs in the live but non-ready daemon with no Device Executor through one bounded maintenance executor under both locks and the matching Anchor. Bootstrap never repairs automatically. Before copying, it inventories every discoverable corrupt object and proves the full Repair Evidence count and bytes, complete repair Receipt, and filesystem safety margin fit both immutable binary maxima and Installation Policy deployment limits; the effective limits and Installation Policy Identity bind the Intent Hash and Receipt. Insufficient capacity changes no state and begins no partial repair. Any interrupted copy remains non-authoritative Repair Evidence Staging. After the exact staged bytes and manifest synchronize, Anchor `PREPARED` promotes that complete set to immutable Repair Evidence; the repair never truncates or rewrites it, and an unverifiable Epoch Open requires Restore unless Cross-Authority Damage instead requires its registered Recovery Bundle Clone. The repair reserves a new range and builds an immutable repair-successor Continuation Descriptor plus one sealed boundary Segment whose first record is a strongly synchronized Audit Repair Boundary embedding the complete Receipt. The canonical descriptor binds root kind, Runtime and History Epoch IDs, epoch-fixed identities, predecessor Audit Continuation Hash, last verified Audit Record Identity, damaged interval, ordered evidence File Hash manifest, sealed boundary Segment Hash, and the Boundary's resulting Audit Record Identity, but excludes every later Segment. Its digest determines the canonical directory name under the fixed Audit root; the path remains a label, and Bootstrap resolves no arbitrary path and verifies the descriptor, hash, ownership, file types, and referenced files without consulting Runtime Metadata. The same fixed-size ordinary pointer used by the Root Continuation contains only that hash; atomic replacement followed by parent-directory synchronization is the Native Authority publication point. The continuation directory contains only regular files owned by the service; symlinks and special files are forbidden. Anchor `PREPARED` names its permanently stored current hash and the candidate Audit Continuation Hash; after pointer publication, Anchor `COMMITTED` replaces the permanent current hash with the candidate. Later immutable Segments continue from the sealed boundary without changing the pointer or continuation identity. The repair never appends to the corrupt active file or replaces the whole journal. A predecessor pointer may abort with no Audit record; a candidate pointer only finalizes forward, and a third pointer or an Anchor/pointer mismatch is Audit Repair Required rather than an invitation to scan.

Audit Pointer Repair is a distinct live-but-non-ready maintenance operation used only when the Anchor's current Audit Continuation Hash and its complete descriptor, Segment chain, and head remain verifiable but the fixed pointer is missing, corrupt, or names another hash. Under Maintenance Capability and both locks, it preserves the complete observed pointer bytes or a typed missing-pointer observation as Repair Evidence, binds the exact Anchor hash, evidence, Installation Policy Identity, Receipt, and Pending Audit Envelope in `PREPARED`, atomically replaces the pointer with a fully synchronized file containing only that Anchor hash, synchronizes the parent directory, and writes Anchor `COMMITTED`. It then appends and strongly synchronizes the exact standalone Receipt before clearing pending state. No scan, alternate valid descriptor, operator-selected hash, or automatic Bootstrap rewrite is accepted. If the Anchor-named descriptor or required files do not verify, pointer repair cannot establish lineage and requires Runtime Restore, or registered Recovery Bundle Clone when same-ID recovery is forbidden.

Every bounded segment header carries 16-byte Runtime and History Epoch IDs plus the epoch's Audit Registry Identity and Audit Head Hash Schema Version; sealed metadata records the epoch-local Event Sequence range, typed Segment Hash `{schema_version, digest[32]}`, and preceding-segment summary. Configured retention appends a Retention Boundary recording the selected sealed-segment range and typed identity and synchronizes it durably. At that synchronization point the covered prefix immediately ceases to belong to the retained chain: all later traversal and Bundle creation ignore residual covered files, which are garbage eligible for idempotent deletion without a second completion record. Existing retained segments and their historical Segment Hash versions are never rewritten. Capacity, append, or reclaim failure before logical removal enters Audit Degraded; failure of the required Retention Boundary durability barrier confirms Storage Barrier Failure, while garbage-reclaim failure after successful logical removal remains Audit Degraded.

By default records contain IDs, model revisions, sizes, hashes, timing, states, and reason codes, never prompt, token, or output content. A Fake Backend can replay Scheduler and Resource Governor decisions, but the journal does not promise MLX numerical replay and never rebuilds Control State. A committed Runtime Identity, Control State successor, or Generation Retention action remains authoritative if a crash leaves it ahead of Audit. Before Control publication, its candidate contains a Pending Audit Envelope with the exact `{major, registry_hash, descriptor_hash}`, assigned Event Sequence, predecessor Audit Head Hash, complete canonical framed bytes, and expected Audit Record Identity; Bootstrap never regenerates it from a state diff. Only the Integrity Serving Profile additionally requires Authority Publication Staging `COMPLETED`. Each response confirms Storage Barrier Failure, never claims rejection or unchanged authority, populates the volatile Barrier Failure Observation, and leaves Readiness false for next-session forward reconciliation. Ordinary Turn append acknowledgement may still follow an OS-buffer write under configured periodic or batched synchronization, so per-Turn fsync remains off the serving path. Every Epoch Open, Control Mutation record, standalone Maintenance Operation Receipt, Retention Boundary, and Clean Shutdown Boundary is a strong barrier before its corresponding state transition completes.

A Runtime Bundle is created only offline after Offline Maintenance Authorization and under the Daemon Instance Lock plus matching Runtime Identity Lease and Anchor. Before staging any output, capture proves Bootstrap did not confirm Cross-Authority Damage and that Metadata and Audit independently verify one already committed boundary; it never reconciles or mutates source state. Storage Capability Missing does not forbid this read-only source operation after daemon exit, but any pending publication, unreconciled authority mismatch, or unverifiable committed boundary rejects capture. A terminal unclosed sequence interval may be represented exactly without writing a Boundary. The affected Runtime can never create a salvage or partial Bundle after Cross-Authority Damage.

Evidence Schema Manifest Hash instead uses its fixed versioned bootstrap encoding outside that registry to avoid self-reference. Historical immutable identities are never rewritten. A new release may explicitly retire a reader only while retaining the kind/version registry entry, fixtures, retirement metadata, and a Compatibility Tool Record binding a permanently retained content-addressed macOS executable bundle. The bundle contains every non-system dynamic library and declares CPU architecture and macOS support. A protected CI path forbids editing or deleting older records, and its merge queue serializes one unique checked successor. Failure blocks additional reader retirements until corrected but is external governance evidence, never an existing Runtime condition or Readiness input. The MVP adds no signing PKI, Sigstore, cosign, or notarization trust root. Outside that envelope the operator must use such a host rather than trust an opportunistic rebuild. Recovery Bundle Registration is a separate offline maintenance publication after current-Policy authorization, daemon shutdown, both locks, a matching Anchor, and terminal reconciliation of every earlier operation. The tool fully revalidates one complete operator-supplied Bundle and must prove from the currently retained Anchor, Audit chain, Continuations, and Retention Boundaries that its equal Runtime ID and captured boundary are an ancestor of current lineage. The MVP stores no permanent ancestry accumulator: if retention has removed any evidence needed for a new proof, registration rejects without mutation and requires a fresh current capture; IDs, epochs, versions, and timestamps are never sufficient substitutes. It proves the standalone Receipt fits and binds predecessor and candidate registered Bundle Hashes, Bundle identity, current Installation Policy Identity, exact lineage proof, and Pending Audit Envelope into one intent. Anchor `PREPARED` names the old and candidate registrations; the next Anchor slot is the native authority publication installing the candidate, after which only the exact Receipt bytes are strongly synchronized to Audit before pending state clears and the operation completes. Later retention cannot invalidate an already committed registration because its Anchor selection and Receipt preserve the proof result. A crash before Anchor publication may abort; one after publication only completes forward. Registration retains no Bundle path or bytes and has no ordinary Readiness effect; Restore or Clone accepts a location only as command input and revalidates every supplied byte to the registered hash. Replacing the selection neither deletes nor makes the predecessor Bundle prune-eligible until ordinary reference closure proves it unreferenced.

The source Audit prefix remains only in the separate immutable Bundle lineage artifact, which is retained until an explicit later prune. Store-only migration preserves both IDs, the selected Control State version, and sequence continuity. Active Hash Migration preserves both IDs, state meaning, and sequence continuity but publishes a version-plus-one successor under the new Semantic or Generation Hash schema. Runtime Metadata Store staging advances monotonically from `PREPARED` to `PUBLISHED`, `AUDITED`, and `COMPLETED`, or from `PREPARED` only to terminal `ABORTED` when construction fails before publication. At most one Authority Publication is non-terminal, so Restore and every other operation first brings it to a terminal phase rather than overwriting it. Every publication follows Anchor `PREPARED` with a fixed Publication Token, kind-specific Native Authority publication, then Anchor `COMMITTED`. Once `PUBLISHED`, any Audit failure leaves authority published and Readiness false; no swap-back or rollback is allowed. `AUDITED` follows durable synchronization of the operation-specific representation, and `COMPLETED` follows pending-evidence clear. Same-ID same-intent resume advances from the persisted phase or returns a bounded terminal tombstone; for Rebind that resumer is only the candidate-build tool retained by digest in Rebind Tool Custody through completion, while a different Intent Hash enters Metadata Repair Required and another operation cannot take over. Bootstrap reconciles Restore or Clone against Epoch Open, Audit repair against Audit Repair Boundary, and Initialization Manifest Repair, Locator Repair, Metadata repair, Audit Pointer Repair, Recovery Bundle Registration, Migration, or prune against its standalone Receipt by exact Operation ID and typed Receipt Hash.
