# Bound Ingress and Keep External I/O Off the Device Loop

The daemon applies global and per-connection Ingress Budgets to negotiated outstanding command count and bytes, Preparing, Warming, active request counts, and output backlog. After structural validation, every command must reserve one outbound slot and its maximum Direct Response bytes before Event Loop admission. The reservation remains charged until the complete frame is written or the connection terminates; enqueue only converts it into actual frame occupancy. If ordinary response capacity is unavailable, a separate single fixed rejection reservation returns the bounded rejection; if neither reservation is available, the connection closes rather than admitting a command it cannot answer. Output cannot consume either reserve. An ordinary command exceeding its remaining count or byte bound returns retryable Overloaded through its reservation before Event Loop admission; for request submission this precedes Request ID, Request State, Residency Demand, Resource Reservation, and fairness accounting. Cancellation enters through independent reserved ingress capacity but keeps socket receive order, so overload cannot block or move it ahead of an earlier command. One connection may own multiple requests under these bounds. The dedicated Device Executor intentionally remains occupied during one certified synchronous Backend operation; this ADR's nonblocking requirement applies to socket, storage, audit, and other external I/O, which must never stall that owner thread.

The bounded outbound queue separately reserves terminal-Status capacity. Effect dependencies and the single socket writer place each complete Direct Response frame before Status or Output caused by that command, while unrelated commands may complete out of Command ID order. The daemon does not wait for client acknowledgement; socket failure leaves delivery unknown and never causes replay. Data and Control Plane Hellos independently freeze effective no-progress and total-completion write durations within binary hard maxima for the connection. Once an oldest required frame is eligible at the writer head, those monotonic deadlines bound its partial writes and never change mid-frame; expiry disconnects the client, releases its reservations, and applies disconnect cancellation rather than dropping the frame, retrying it, or permitting a slow byte trickle to retain capacity forever. A terminal update is never silently discarded: if its reserved capacity is exhausted, the daemon disconnects the client and applies the same outcome rather than blocking or growing the queue. For one request, queued non-terminal Status Updates wholly superseded by a newer snapshot may coalesce, and the replacement declares History Gap. Socket-write failure has the same disconnect outcome and never causes Event Loop retransmission. Terminal Tombstones are bounded by per-connection and global counts plus retention time and contain no output content. A bounded connection-local Request High-Water Mark lets authorized lookup return Gone after eviction without a permanent completed-ID table. Command IDs are nonzero unsigned 64-bit values and never wrap; accepting `u64::MAX` returns `command_ingress_closed`, stops reading later command frames, and preserves existing-request Status, Output, and disconnect detection. A separately bounded Core Event Reserve remains available to cancellation, disconnect, Critical, Device Executor Failure, shutdown, and repair events. Expensive Control Mutation validation, hashing, and durable preparation run on a bounded executor with at most one mutation in flight while the prior Snapshot remains effective; only the prepared result returns to the Runtime Event Loop for complete Control Mutation Token revalidation and Turn-boundary activation. Audit records similarly flow in Event Sequence order to one bounded single-writer queue, whose saturation enters Audit Degraded instead of blocking the Event Loop. Runtime metrics use only fixed-enumeration or explicitly bounded dimensions.
