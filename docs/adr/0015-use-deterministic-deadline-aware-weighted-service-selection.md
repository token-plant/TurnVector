# Use Deterministic Deadline-Aware Weighted Service Selection

After resource-safety filtering, a Work Candidate enters the Urgent Set when daemon-owned Monotonic Time reaches its Latest Safe Start, defined as its timing obligation minus its Deadline Cost Bound; a Batch uses the earliest value across every member and is infeasible if any obligation or Progress Bound cannot be met. The Daemon clock is authoritative for deadlines, waits, evidence freshness, and scheduling decisions. The Worker reports only locally measured durations, sample sequences, and outcomes, never absolute scheduling timestamps, so no cross-process clock alignment is required. The Scheduler selects earliest Latest Safe Start, then smallest Model Ledger, then stable Candidate ID. With no urgent candidate, it selects the Runnable stable Model ID with the smallest ledger, where all Revisions share one account and each Turn adds only Worker-measured Engine Service divided by Model Weight. Runtime Overhead never changes fair share. Snapshots and Plans carry Scheduler, Backend, and Safety generations, and Cost Profiles switch only between Turns.
