# Use Deterministic Deadline-Aware Weighted Service Selection

Every active Owner-Thread Support Budget includes finite build-generated per-operation and per-pool Support Start Count Bounds for each configured half-open horizon. The sole Core Support Charge Ledger enforces them with fixed typed physical start credits. Admission obtains actual initial Support Operation Obligations and reserves each request's complete finite Support Outstanding Credit Vector from the unbatched finite request closure. A later Plan creates one obligation for each actual batch/model-scoped Backend support call: the obligation occupies one vector claim in every funding Future Turn Support Entitlement but owns exactly one physical credit regardless of member count. Candidate Formation uses one typed funding claim per affected request and may mix Admission-reserved initial claims with entitlement-vector claims without double funding. Unstarted obligations may split, merge, rebind, or close only with exact call-scope, typed-funding-claim, vector, and physical-capacity conservation; an active obligation is frozen. Optional ordinary work must atomically obtain one typed Ordinary Reservation Claim, its matching obligation, and one legal credit in `begin_support`, while post-load/post-observation description work and first/next safety sampling consume lifecycle reserves established before their trigger can make them mandatory. Active records, linked entitlement claims, and consumed credits remain retained through the Catalog Retention Horizon, so consecutive Turns, member cancellation, or sequential churn cannot reuse capacity merely because concurrent request count fell. Admission rejects when any required timing capacity, vector slot, physical credit, or lifecycle reserve is unavailable; mandatory-completion and safety-sampling pools are nonborrowable.

A measured Turn-envelope excess remains a certified Bound Violation: Core preserves a trustworthy Receipt, quarantines the most specific affected Capability Key, and then advances Runtime Overhead Generation once through the non-Control evidence-invalidation owner. Generation invalidation never substitutes for quarantine.

After resource-safety filtering, a Work Candidate enters the Urgent Set when daemon-owned Monotonic Time reaches its Latest Safe Start, defined as its timing obligation minus its Deadline Cost Bound; a Batch uses the earliest value across every member and is infeasible if any obligation or Progress Bound cannot be met. The daemon's monotonic clock is authoritative for deadlines, waits, evidence freshness, scheduling decisions, and Device Executor duration measurement. The Scheduler selects earliest Latest Safe Start, then smallest Model Ledger, then stable Candidate ID. With no urgent candidate, it selects the Runnable stable Model ID with the smallest ledger, where all Revisions share one account and each Turn adds only Device Executor-measured Engine Service divided by Model Weight. Runtime Overhead never changes fair share. Urgency never interrupts an in-flight Turn. Every fresh Scheduling Snapshot while a Timing Commitment survives follows the same synchronized scheduling cut, whether triggered by the first runnable plan, Receipt, Plan Rejection, local stale, support Result, or idle re-entry; no path continues inline or dequeues later ordinary work across that cut. This is why every Prefill Turn must expose exactly one certified chunk boundary. Snapshots and Plans carry Scheduler, Backend, Safety, and Runtime Overhead generations plus the exact daemon-associated Bound Set and admitted Stale Plan Disposition ceiling, and the Event Loop rechecks them immediately before Backend execution. A mismatch submits one Local Stale Plan Core Event with no Backend call or fabricated Plan Rejection; the currently active qualified disposition bound must fit that frozen ceiling and never borrows authority from the stale Set. Cost Profiles switch only between Turns.

Latest Safe Start uses one checked Deadline Cost Bound derived from an exact applicable Runtime Overhead Bound Set. Let `B` be the greater of two disjoint envelopes: pre-call intrinsic overhead plus certified Engine Service plus Receipt validation, Core commit, and Output Publication; or pre-call intrinsic overhead plus the complete Plan Rejection call, rejection transition, and one intrinsic fresh-Snapshot/replanning disposition with zero Engine Service. The Event Loop captures the `execute_turn` start and end once and assigns the whole interval only after reading its typed result. Every support operation instead owns one complete daemon envelope from its typed Ordinary Reservation Claim, obligation, credit, and active-record creation or standalone pending-obligation `begin_support` transition through preparation, direct call, validation, accepted Core transition, and immediate in-memory Effects; its direct call remains an independent watchdog subspan. A Receipt, rejection, local-stale, cancellation, or prior support Result can only leave the next operation obligation pending, rebind an unstarted scope, or close it on typed causal impossibility. After that predecessor envelope ends, a standalone Core `begin_support` transition converts the pending obligation and starts the next support envelope, so no Core transition belongs to both spans. The intrinsic fresh disposition ends before any `form_candidates` preparation, so rejection-, local-stale-, or cancellation-membership-change-driven Candidate Formation consumes its already funded operation obligation and is measured only as a support envelope. Every non-Backend Core Event allowed ahead of a fresh Snapshot likewise owns one Sequenced Event envelope. Intrinsic Turn, support, and sequenced-event envelopes are mutually exclusive. When a fresh disposition selects a replacement candidate, the replacement partition starts after any separate Candidate Formation and does not remeasure the same intrinsic Snapshot or selection interval.

A Plan Rejection destroys the old Plan and forces a fresh Scheduling Snapshot; it never substitutes work or reuses the old bound. For each configured positive horizon `H`, the Bound Set supplies `support_interference(H)`, the checked maximum active-charge and all-unstarted-obligation complete support-envelope capacity, including `conditional` and `pending` states in any arbitrarily aligned half-open interval, and `sequenced_event_interference(H)`, the externally qualified maximum complete non-Backend Core-event work from the frozen prefix plus fixed mandatory-crossing allowance. Mandatory support includes Admission-created initial Materialization and Candidate Formation, accepted-Receipt observation and any separately obligated continuation Candidate Formation, the mutually exclusive rejection/local-stale formation path, terminal cancellation membership-change formation, post-load/post-observation description revalidation, first/next safety sampling, and ownership release. Admission atomically obtains the three initial obligations and creates one reusable Future Turn Support Entitlement with a complete outstanding-credit vector against later Admission and ordinary support. Each Plan creates one shared Receipt-observation obligation, one conditional continuation-formation obligation, and the alternative rejection/local-stale formation obligation; each is jointly funded by all members and carries one distinct physical credit; cancellation rebinds or splits unstarted obligations and funds terminal membership-change formation only when removing a request invalidates an existing candidate. Each outstanding claim reduces request-specific headroom without starting an envelope timer, and any unused unbatched reserve remains attached to its entitlement rather than becoming available to later Admission. After a complete causal predecessor envelope ends, a standalone `begin_support` transition converts the pending obligation to an active absolute-time charge immediately before preparation; it may close only when a typed result proves its causal operation impossible. The scheduling cut prevents later ordinary events from overtaking the fresh Snapshot; later safety/cancellation work consumes the already bounded crossing allowance, then coalesces or defers, or invalidates affected commitments and fail-stops when deferral is illegal. Admission proves every authorized future case has a certified `H` satisfying `B + support_interference(H) + sequenced_event_interference(H) <= H` and reserves the maximum across that finite closure; deadline-cost composition later selects the smallest valid horizon for the exact Candidate. The Deadline Cost is that checked sum, and no matching horizon makes the Candidate infeasible. Core's entitlement-vector, operation-obligation, active-charge, and lifecycle-reserve ledger enforces the support algebra, while the finite event registry, Core Event Reserve, scheduling cut, and crossing allowance enforce event interference without a second support ledger. If the fresh disposition cannot produce a candidate whose bound still fits every frozen Timing Commitment, Core emits SLO Risk and blocks related new Admission rather than silently widening the promise.

The bound-set identity includes the exact two-level TurnVector Daemon Build Identity and Runtime Overhead Catalog, complete Configuration Snapshot identity, Hot-Path maxima, one fresh Environment Fingerprint, Admission's exact finite Certification Applicability Selection with every selected Certification Record and Case Bound Table, Backend Operation Bound Set, complete Turn-result case table, span schema, exact active qualified Owner-Thread Support Budget and sliding-horizon table, Sequenced Event Interference Bound, and companion Stale Plan Disposition Bound. Admission alone constructs the Set from its immutable selection and those already active lifecycle descriptors; runtime instrumentation only measures and enforces the Core-supplied descriptor. The Support Charge Ledger retains active charges, linked entitlement claims, operation obligations, and lifecycle reserves through their exact typed terminal and build-derived Catalog Retention Horizon rules, so a longer qualified successor cannot forget history. Before changed-Configuration publication, the daemon matcher alone selects and qualifies one exact immutable successor witness; Core verifies its identity/current generation and carries the complete ledger, but never selects lifecycle evidence. Identity drift or a Turn-envelope measured excess advances Runtime Overhead Generation through the sole applicable Core owner, invalidates older not-started Snapshots and Plans, and triggers Profile Revalidation before further dispatch. A measured support, sequenced-event, or local-stale envelope excess instead invalidates Lifecycle Overhead Qualification and invokes process-wide fail-stop before another Backend or scheduling call. Revalidation preserves the original promise and evidence while installing a current conservative feasibility witness. Online observations may invalidate or diagnose evidence but cannot widen it, become Cost Profile state, or add service to a Model Ledger.

Control publication Store and Audit I/O is outside request Deadline Cost only because the closed Runtime Closure Gate first blocks new request liability and drives every accepted request, Turn Plan, Timing Commitment, Future Turn Support Entitlement, request Backend ownership, pending release, and output reservation to a stable zero witness. The Event Loop may pause for publication only after revalidating that witness under the gate. This is a request-quiescence rule, not an assumption that persistence latency is negligible or free.
