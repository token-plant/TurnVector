# Distinguish Plan Rejection from Started Turn Outcomes

A Turn Plan that fails pre-execution Candidate or Generation Vector validation returns a Plan Rejection and audited Domain Rejection, consumes no Engine Service, and produces no Turn Receipt. Once Backend execution begins, exactly one synchronized Turn Receipt is required while the Executor remains alive. Batch Receipts contain per-request Member Outcomes, but recovery is per member only when the Backend proves persistent-state isolation; otherwise the entire Batch is quarantined. Output remains staged until the Scheduler accepts the Receipt and atomically commits request state, after which explicitly ordered Effects enqueue at most one Output Frame per member into capacity reserved before execution; successful enqueue is Output Publication. Strictly contiguous Event Sequence resolves cancellation races: cancellation command acceptance confirms only that ordering; if ordered first it enters Cancel Pending and discards staged output at the safe boundary, while a cancellation ordered after Receipt commit and Output Publication cannot revoke visible output. An independent Status Update reports the actual terminal state even when a final Output Frame also carries a terminal reason. Duplicate or late Effect Results are rejected and never publish or commit a second time.
