# Support Open Work Kinds Through Fixed Scheduling Semantics

Execution Backends may introduce new Work Kinds without adding Work Kind branches or plugins to the Scheduler, but each exact Capability Key still requires an applicable Certification Record before shared scheduling. The Scheduler supplies eligible request handles and common constraints; the Backend returns a deterministic bounded set with at most one immutable candidate per Model ID, Execution Phase, Service Class, and configured batch bucket, never enumerating arbitrary request subsets or attaching priority. A Prefill candidate describes only the next resumable Prefill Chunk opportunity and its one-Turn bounds; it never represents or authorizes the complete remaining prompt. A Batch candidate must meet every member's timing obligation and uses their earliest Latest Safe Start. Every Work Kind maps to the same fixed scheduling semantics, and all Revisions and work for one Model ID share one Model Ledger. An exact Capability Key without an applicable Certification Record is explicitly rejected in shared mode rather than probed at runtime or routed automatically to Exclusive Mode.
